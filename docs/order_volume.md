# Бустинг с лагами для объёма заказов

Stream processor оценивает почасовой объём `mock_orders` после обычных проверок.
HistGradientBoostingRegressor прогнозирует количество заказов по календарю и предыдущим
наблюдениям в UTC. Модель обучается на истории источника `mock`, поэтому не предполагает
наличия сезонности, которой нет в данных. Текущий мок может сохранять постоянный объём.

Профиль партии содержит `order_volume`: количество заказов с `created_at` внутри
заявленного завершённого часа либо причину, почему наблюдение недоступно. Полная
пустая партия даёт ноль. Неполные периоды, невалидные даты и партии с заказами из
других часов исключаются из ML. Пропущенная загрузка не превращается в ноль;
поступление данных контролируется отдельной ежедневной проверкой.

## Обучение и использование

DAG `orders_volume_training` запускается в 02:00 UTC. Для начала работы нужно около
28 дней истории: 7 дней для начальных лагов, 14 для обучения и 7 для калибровки.
Последний час перед сроком проверки оставляется на доставку данных.
Повторная загрузка часа заменяет предыдущую, даже если исправленная партия непригодна.
Будущие относительно срока обучения поступления исключаются. Если хотя бы одного
целевого часа или достаточной истории его лагов не хватает, обучение получает SKIPPED;
уже сохранённая совместимая модель остаётся доступной.

Признаки включают час, день недели, выходной, лаги за 1, 2, 3, 24, 48 и 168 часов,
а также среднее, медиану, стандартное отклонение и число доступных наблюдений за
предшествующие 6, 24 и 168 часов. Для каждой обучающей строки и рабочего прогноза
используются только предыдущие часы, поступившие к началу прогнозируемого часа.
Текущее значение не входит в признаки. Поэтому опоздавшая партия за предыдущий час
остаётся пропущенным лагом, даже если она появилась ко времени выполнения проверки.
Бустинг поддерживает пропуски; они не заменяются нулями. Нужны как минимум 80% часов
предыдущей недели и наблюдения за тот же час вчера и неделю назад. Иначе прогноз
получает SKIPPED с причиной `insufficient_lag_history`.

Три регрессора оценивают ожидаемый объём и квантили 0.05 и 0.95. На последних 7 днях
интервал расширяется по 99-му эмпирическому процентилю нормированного выхода факта
за исходные границы. Минимальная ширина с каждой стороны — 20% от `max(expected, 1)`;
нижняя граница неотрицательна. Факт вне итогового интервала даёт WARN. Калибровочная
история не используется для обучения деревьев; случайная ранняя остановка отключена.
Квантили и поправка задают чувствительность, но не гарантируют долю ложных тревог
на новых данных. Аномалии в истории могут влиять на лаги и расширять интервал.

Модели хранятся в `order_volume_models` вместе с параметрами, версией sklearn,
границами истории, идентификаторами партий и хешем обучающих данных. Обработчик
выбирает последнюю модель, срок обучения которой не позже начала проверяемого часа.
Модель загружается из БД и кэшируется в памяти; обучение при обработке партии не запускается.
Версия признаков проверяется независимо от схемы raw: полная пустая партия тоже
может быть оценена. Первая модель появляется после накопления пригодной истории.

## Результаты и восстановление

`order_volume_predictions` сохраняет результат по `evaluation_id`: PASS, WARN,
SKIPPED или ERROR, фактический и ожидаемый объём, отклонение, порог и версию модели.
При WARN создаётся запись в существующей таблице аномалий и событие `anomaly.detected`;
они доступны через обычный API и интерфейс аномалий. Решение качества PASS/WARN/BLOCK
при этом не меняется. Сохраняются также границы интервала, вектор признаков и
идентификаторы исторических партий. Ошибка расчёта модели сохраняется как ERROR и не отменяет
обычные проверки. Ошибки записи и отправки события допускают повтор обработки.

Повтор события использует сохранённый прогноз и тот же идентификатор аномалии.
Для нового прогноза, в том числе после обучения или исправления модели, выполните
явную переоценку с новым `request-id`. Переоценка также не использует будущую историю.

Примените миграцию `0005` до запуска обновлённых сервисов. В Docker Compose зависимости
включены; образ Airflow нужно пересобрать. Для локального запуска:

```sh
uv sync --extra ml --extra storage
uv run --extra ml --extra storage alembic -c storage/postgres/alembic.ini upgrade head
uv run --extra ml python -m services.ml.train_order_volume
```

Нужна `DATABASE_URL`. Ручная команда использует тот же путь обучения, что и DAG;
`--cutoff` позволяет явно задать срок в ISO-формате с часовым поясом. Обучение и
обработчик используют одну фиксированную версию sklearn. При несовпадении окружений
прогноз получает ERROR и требуется переобучение. Отсутствующая модель даёт SKIPPED.
Версия модели — `order-volume-lag-boost-v2`: прежние календарные модели не выбираются.
Почасовые наблюдения версии `order-volume-v1` совместимы с новым обучением,
поэтому пересчитывать их не требуется. Прогнозы старых оценок остаются неизменными.

Строгие проверки, регрессия временного объёма и многомерный анализ решают разные
задачи. Сейчас действуют первые два механизма; общие профили сохраняются как основа
для последующего многомерного детектора.

# Application-layer #4: выполнение и история качества

Зона ответственности — backend и frontend. База этой итерации — main после PR #17.
Контракты Evaluation, CheckExecution и методы их хранения реализованы коллегами.

## Два результата

1. `feat: add quality evaluation history API` — пагинированное чтение истории,
   подробности с актуальными исполнениями, scopes без итоговых результатов,
   readiness новых таблиц, API- и PostgreSQL-проверки.
2. `feat: show quality evaluation history in dashboard` — выбор расчёта, отдельные
   состояния выполнения/качества/policy, диагностика и попытки, прямые ссылки,
   три оформления, браузерные проверки и документация.

Критерий: расчёт, сохранённый через общий storage, доступен через API и браузер;
изменение исполнения видно после ручного обновления. Старый /quality поддерживает
записи без Evaluation. Ошибки истории не маскируются этим режимом.

## План после PR

1. Независимо: просмотр запусков pipelines. Вход — PipelineRun и существующий
   репозиторий. Добавить каталог/историю через application read-адаптер и экран.
   Результат — реальный запуск Airflow, его состояние и ошибка видны после обновления.
   Связь запуска с dataset отдельно согласовать, не выводить её из похожих ID.
2. Независимо: история метрик dataset. Вход — MetricPoint, профили и существующие
   методы чтения. Результат — история выбранной метрики/колонки с корректными
   версиями статистики, временами и отсутствующими значениями.
3. По ответам quality/storage: уточнить ход выполнения и времена. Вход — подтверждённые
   контракты из таблицы выше. Результат — UI показывает новые поля без собственных догадок.
4. После готовности Incident Intelligence: API и экраны инцидентов, lineage, RCA и
   impact. Вход — рабочие контракты, read-методы и сохраняемые примеры. Результат —
   реальный инцидент и его связи читаются через приложение. Старое demo контрактом не является.

В этой сессии нет запуска переоценки через API, редактирования конфигурации,
алгоритмов качества, метрик, pipelines, инцидентов, lineage или Agent.
Коммиты и PR создаёт пользователь. Внутренние commits.md и handoff.md не включаются.

## Проверка реализации

Локально: PostgreSQL 18 в отдельном тестовом кластере, Edge headless.
Полный набор `tests/application`: 136 passed без пропусков. После последних
изменений интерфейсов репозиториев и ширины таблицы дополнительно прошли
50 API-проверок и 16 PostgreSQL/мобильных проверок. Ruff, проверка аннотаций,
форматирование Python, синтаксис JavaScript и git diff --check прошли.

Проверены HTTP-контракты, SQL-пагинация, снимок чтения, отдельные save_execution,
readiness при отсутствии таблицы, прямые ссылки, история браузера, ручное
обновление, ошибки/retry, запоздалый ответ, три оформления и ширина 390 px.
В существующем CI используется PostgreSQL 16; удалённый CI в этой сессии не запускался.
Локальные скриншоты находятся в игнорируемом test-results/evaluations/.

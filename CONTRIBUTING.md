# Правила комментариев и докстрингов

## Язык и назначение

Комментарии и докстринги в коде пишем на английском. Пользовательские
сообщения и проектная документация могут быть на русском.

Докстринг описывает контракт: назначение объекта, значимое поведение и условия
использования. Комментарий возле реализации объясняет причину решения,
ограничение или неочевидный порядок действий. Не пересказываем код и имена.

## Где нужны докстринги

- У содержательного модуля: его ответственность и границы.
- У публичного класса: роль, общие гарантии и существенные ограничения.
- У методов интерфейса `Protocol`: правила, на которые полагаются вызывающие
  компоненты, включая отсутствие результата, порядок данных и побочные эффекты.
- У основных операций сервисов и функций с неочевидным поведением.
- У внутренних функций, если алгоритм или ограничения требуют пояснений.

Пустые пакетные модули, очевидные свойства, конструкторы с простым присваиванием,
тонкие делегирующие методы, валидаторы с понятными проверками и обработчики,
полностью описанные интерфейсом, могут обходиться без докстринга. В тестах
обычно достаточно имени сценария; документируем только неочевидные условия.
Для миграций достаточно описания изменения на уровне модуля, если отдельные
операции не имеют дополнительных ограничений.

## Формат и объём

Используем тройные двойные кавычки. Первая строка — законченное краткое
предложение с точкой. У функции оно описывает действие, у класса — роль.
Подробности отделяем пустой строкой; закрывающие кавычки многострочного
докстринга ставим на отдельной строке. По возможности укладываем текст в
88 символов на строку без ухудшения читаемости.

Для простой операции достаточно одного предложения. Для особых условий
добавляем абзац. Сложные контракты оформляем в Google-style с разделами
`Args:`, `Returns:`, `Raises:` и при необходимости `Yields:` или `Examples:`.
Разделы добавляем только при наличии полезного содержания; одинаковый объём
для всех функций не требуется. Типы из аннотаций не повторяем.

```python
def get_batch(dataset_id: str, batch_id: str) -> Batch | None:
    """Return the batch identified within a dataset, or None if absent."""
```

## Что описывать

- Смысл `None`, нуля, пустой коллекции и отсутствующих данных.
- Единицы измерения, часовой пояс, включение границ временного интервала.
- Порядок сортировки, фильтрацию, ограничения выборки и ответственность вызывающего кода.
- Изменение состояния, запись в хранилище, публикацию событий и владение ресурсами.
- Идемпотентность, ключи повторных вызовов, блокировки и границы транзакций.
- Условия ожидаемых ошибок, повторных попыток и сохранения промежуточного результата.

Не обещаем гарантий, которых реализация не обеспечивает. `Raises:` содержит
существенные для вызывающего кода ошибки, а не все возможные исключения зависимостей.

## Единый источник описания

Общий контракт храним в интерфейсе. В реализации описываем дополнительные
особенности хранилища или транспорта, не копируя весь контракт. Докстринг
класса не заменяет описание существенных параметров и поведения его методов.
Большие архитектурные объяснения и инструкции запуска храним в документации;
необходимые для корректного вызова ограничения оставляем возле API.

В JavaScript применяем те же критерии к JSDoc (`/** ... */`); обычные
комментарии в JavaScript и SQL объясняют решения, где это необходимо.
Не добавляем комментарии ради формального покрытия.

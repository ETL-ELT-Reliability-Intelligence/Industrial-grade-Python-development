# Система мониторинга и анализа надёжности ETL/ELT-пайплайнов

## 0 итерация - планирование и проектирование

### Описание системы

Отслеживает качество данных и состояние их обработки, выявляет отклонения, связывает связанные проблемы в инциденты и помогает определить возможную первопричину и зону влияния.

Со схемами системы можно ознакомиться в разделе [docs](./docs/).

Документация backend/frontend находится отдельно в [docs/application](./docs/application/): [план итераций](./docs/application/plan.md).

### Возможный вариант структура репозитория
```text
./
├── services/
│   ├── ingestion/
│   ├── stream_processor/
│   ├── incident_engine/
│   ├── backend/
│   ├── agent/
│   └── frontend/
│
├── contracts/ # общие модели данных и контракты взаимодействия между компонентами
├── data_quality/ # общая логика проверок качества данных и правил принятия решений
├── pipelines/ # описание пакетной обработки и ELT-процессов
│   ├── airflow/
│   └── dbt/
│
├── database/ # миграции и схема служебной базы данных
├── tests/
├── docs/
├── scripts/ # скрипты для запуска и другие
├── docker-compose.yml
└── pyproject.toml
```

## 1 итерация - закрепление контрактов взаимодействия отдельных компонентов и их реализация

Ульянова Е.А. занималась базовой версией модуля проверок качества данных, а именно проверками актуальности данных, пропусков, количества записей и схемы, а также политикой принятия решений (PASS, WARN, BLOCK). Реализовала контракты, обработку ошибок и модульные тесты для данной части. Впоследствии перевела все контракты с dataclass на Pydantic v2, чтобы отказаться от ручной реализации и поддержки валидации, проверки типов и сериализации, используя единый стандарт для всех компонентов (решила сделать сразу, пока проект не разросся). Также унифицировала события с учётом важных изменений, предложенных в PR другого участника проекта Михаила.

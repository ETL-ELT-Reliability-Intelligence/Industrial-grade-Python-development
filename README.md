# Система мониторинга и анализа надёжности ETL/ELT-пайплайнов

## 0 итерация - планирование и проектирование

### Описание системы

Отслеживает качество данных и состояние их обработки, выявляет отклонения, связывает связанные проблемы в инциденты и помогает определить возможную первопричину и зону влияния.

Со схемами системы можно ознакомиться в разделе [docs](./docs/).

Документация backend/frontend находится отдельно в [docs/application](./docs/application/): [план итераций](./docs/application/plan.md).

### Возможный вариант структура репозитория
```text
./
├── services/
│   ├── ingestion/
│   ├── stream_processor/
│   ├── incident_engine/
│   ├── backend/
│   ├── agent/

│
├── contracts/ # общие модели данных и контракты взаимодействия между компонентами
├── data_quality/ # общая логика проверок качества данных и правил принятия решений
├── pipelines/ # описание пакетной обработки и ELT-процессов
│   ├── airflow/

│
├── database/ # миграции и схема служебной базы данных
├── tests/
├── docs/
├── scripts/ # скрипты для запуска и другие
├── docker-compose.yml
└── pyproject.toml
```

В процессе вместо database добавили:
```text
├── storage/ # доступ к данным; postgres/migrations/ — миграции схемы
├── infra/ # вспомогательные настройки сервисов; postgres/ — начальная настройка БД
```

## 1 итерация - закрепление контрактов взаимодействия отдельных компонентов и их реализация

### Ульянова Е.А.
Занималась базовой версией модуля проверок качества данных, а именно проверками актуальности данных, пропусков, количества записей и схемы, а также политикой принятия решений (PASS, WARN, BLOCK). Реализовала контракты, обработку ошибок и модульные тесты для данной части. Впоследствии перевела все контракты с dataclass на Pydantic v2, чтобы отказаться от ручной реализации и поддержки валидации, проверки типов и сериализации, используя единый стандарт для всех компонентов (решила сделать сразу, пока проект не разросся). Также унифицировала события с учётом важных изменений, предложенных в PR другого участника проекта Михаила.

Для устранения расхождение настроек, конфликтов портов и случайного использования разных баз при запуске компонентов перенесла в корневой docker-compose.yml проверку готовности БД и создание тестовой базы, удалила дублирующий Compose из infra.

Добавлен GitHub Actions workflow, запускаемый при создании и обновлении PR, push в `main` и вручную. Он включает пять независимых jobs (тесты и ruff).

### Гайнутдинов М.Р.
В рамках application-layer реализованы API и экран для просмотра датасетов, загрузок и сохранённых результатов проверок качества из postgreSQL. Так я проверил взаимодействие приложения с текущими контрактами хранения данных. Старая демка (demo) сохранена отдельно. Семантику некоторых данных и недостающие возможности чтения ещё предстоит согласовать

## 2 итерация - объединение компонентов в единый автоматизированно работающий пайплайн
На данный момент реализован демонстрационный сценарий, запускаемый командой python -m services.backend.seed: создаются тестовые записи о загрузках, выполняются проверки качества на заданных наблюдениях, рассчитывается решение policy и сохраняются результаты в PostgreSQL. Backend и интерфейс позволяют просматривать сохранённые данные. Автоматическое получение наблюдений из Ingestion и обработка событий Kafka пока не подключены.
